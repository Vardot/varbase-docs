# Plan Redirects for a New Site

When a site is relaunched, its old addresses still live in search results, bookmarks and other sites' links. A redirect for each one keeps visitors and search rankings. Treat the redirect map as a deliverable with an owner and a deadline.

## Steps

1. Export the old site's addresses, especially the most visited ones and those linked from other sites. The client's analytics hold this.
2. Map each one to its new address.
3. Import the list before launch, then test the top addresses on launch day.
4. Watch **Fix 404 pages** weekly in the first months, then monthly. See [Fix a Broken Link](fix-a-broken-link.md).

## Questions Clients Ask

- **Can the old domain or the address without www send visitors to the main domain?** Yes, with domain redirects (the **Domain redirects** tab of **URL redirects**). It involves the client's IT team and domain registrar; start early. See [URL Redirects](url-redirects.md#domain-redirects).

## Planning Notes

- Assumption: importing a prepared map takes hours; building it is the real work.
- Avoid redirect chains and loops: an address that redirects to another redirect, or two that redirect to each other.

## Launch Checklist

1. Every menu link leads to a published page.
2. **Fix 404 pages** is cleared of real problems.
3. The redirect list from the old site is imported and tested.
4. Breadcrumbs and the active trail behave correctly for each content type.
5. The main menu works with a keyboard and on a phone.
